
## MODULE 1 — User Registration & Authentication

### FR-AUTH-001 — Mobile OTP Registration

- [ ] User can register with mobile number
- [ ] OTP is sent to mobile number on registration
- [ ] OTP verification blocks account creation until verified
- [ ] OTP expires after a set time window
- [ ] Resend OTP option available

### FR-AUTH-002 — Duplicate Prevention

- [ ] System blocks duplicate mobile number registration
- [ ] System blocks duplicate National ID number
- [ ] System blocks duplicate TIN number (for organizations)
- [ ] Error message clearly tells user which field is duplicated

### FR-AUTH-003 — Organization Document Upload

- [ ] Organization users can upload Trade License
- [ ] Organization users can upload TIN Certificate
- [ ] Organization users can upload Business Registration Certificate
- [ ] All three documents required before KYC submission for org users

### FR-AUTH-004 — Login

- [ ] User can log in with mobile number + password
- [ ] User can log in with email + password
- [ ] Invalid credentials return clear error message

### FR-AUTH-005 — Password Reset

- [ ] Forgot password flow sends OTP to mobile
- [ ] OTP verification required before new password is accepted
- [ ] Password reset confirmation shown after success

### FR-AUTH-006 — Password Security

- [ ] Passwords stored using bcrypt or equivalent secure hash
- [ ] Plain text passwords never stored or logged

- [ ] Evaluation officer can see list of assets ready for evaluation (status `approved`, no existing evaluation)
- [ ] Evaluation officer can schedule inspection with date and notes
- [ ] Asset status changes to `under_evaluation` on scheduling
- [ ] Assets with rejected evaluations reappear in eligible list

### FR-EVAL-002 — Record Valuation

- [ ] Evaluation officer can record valuation amount
- [ ] Evaluation officer can record reserve price recommendation
- [ ] Currency field recorded (ETB)

### FR-EVAL-003 — Upload Photographs

- [ ] Evaluation officer can upload multiple photos
- [ ] Photos stored and viewable in evaluation record

### FR-EVAL-004 — Upload Evaluation Report

- [ ] Evaluation officer can upload evaluation report PDF
- [ ] Report stored and accessible in evaluation record

### FR-EVAL-005 — Recommend Approval or Rejection

- [ ] Evaluation officer can submit recommendation (approve or reject)
- [ ] Submitting recommendation sets evaluation to `completed`
- [ ] Asset status does NOT change to `evaluated` at this point
- [ ] Super admin notified when evaluation hits `completed`

### FR-EVAL-006 — Super Admin Final Approval

- [ ] Super admin can approve completed evaluation → asset becomes `evaluated`
- [ ] Super admin can reject completed evaluation → asset returns to `approved` for re-evaluation
- [ ] Evaluation officer cannot approve their own evaluation (RBAC enforced)
- [ ] Only `evaluated` assets can proceed to auction creation

## MODULE 6 — Auction Management

### FR-AUC-001 — Create Auction

- [ ] Auction manager can create auction
- [ ] Auction manager cannot publish auction (super admin only)
- [ ] Auction starts in `pending_approval` status

### FR-AUC-002 — Link Assets

- [ ] Single asset auction: one evaluated asset linked via asset picker
- [ ] Multi-asset auction: multiple evaluated assets linked with individual reserve prices
- [ ] Only `evaluated` assets appear in eligible assets picker
- [ ] Assets already in active auction excluded from picker
- [ ] All linked assets move to `in_auction` on publish

### FR-AUC-003 — Define Auction Fields

- [ ] Auction Title (required)
- [ ] Auction Description
- [ ] Start Date and Time (required)
- [ ] End Date and Time (required, must be after start)
- [ ] Reserve Price per asset (required)
- [ ] Document Price / Fee (required)
- [ ] CPO Percentage (required, 1-100)
- [ ] Auction Category
- [ ] Auction Conditions

### FR-AUC-004 — Published After Approval

- [ ] Super admin reviews auction in `pending_approval`
- [ ] Super admin publishes → auction becomes `published`
- [ ] Super admin notified when new auction enters `pending_approval`
- [ ] Auction manager notified when auction is published

### FR-AUC-005 — Visible to Bidders

- [ ] Published auctions appear in bidder browse list
- [ ] Browse list defaults to published only
- [ ] Auction detail shows title, description, dates, reserve, document fee, images, documents (gated)

### FR-AUC-006 — Suspended Auction

- [ ] Staff can suspend a published auction
- [ ] Suspended auction prevents new payments, CPO submissions, and bids
- [ ] Suspended auctions not shown in default browse list

## MODULE 9 — CPO Management

### FR-CPO-001 — Upload CPO Document

- [ ] Bidder can select assets they want to bid on before uploading CPO
- [ ] System calculates required CPO amount = `cpo_percentage × SUM(selected asset reserve prices)`
- [ ] Required CPO amount shown clearly to bidder before upload
- [ ] Bidder uploads CPO document (PDF or image)
- [ ] Selected asset IDs stored on CPO record
- [ ] Required CPO amount stored on CPO record

### FR-CPO-002 — Staff Review

- [ ] CSO can view all pending CPO submissions
- [ ] CSO can preview CPO document
- [ ] CSO can see required CPO amount vs declared amount
- [ ] CSO can see which assets bidder selected

### FR-CPO-003 — Approve / Reject

- [ ] CSO can approve CPO with expiry date
- [ ] CSO can reject CPO with reason
- [ ] Only CSO can approve/reject CPOs (RBAC enforced at service layer)
- [ ] Expired CPOs do not pass bid gate

### FR-CPO-004 — CPO Statuses

- [ ] `pending` on submission
- [ ] `approved` after CSO approval
- [ ] `rejected` after CSO rejection

### FR-CPO-005 — CPO Notifications

- [ ] Bidder notified in-app on CPO approval
- [ ] Bidder notified in-app on CPO rejection with reason
- [ ] Bidder notified via SMS on CPO status change
- [ ] Bidder notified via email on CPO status change

## MODULE 10 — Closed Bid Submission

### FR-BID-001 — Submit Bid Before Close

- [ ] Bidder with approved KYC, payment, and CPO can submit bid
- [ ] Bid submission blocked before auction start date
- [ ] Bid submission blocked after auction end date
- [ ] For multi-asset auctions: bidder submits one bid per selected asset
- [ ] Bid amount must meet or exceed asset reserve price

### FR-BID-002 — Bidder Sees Own Bids Only

- [ ] Bidder can view their own bids at `GET /bids/my`
- [ ] Bidder cannot access another bidder's bid details
- [ ] Staff can see all bids across all auctions

### FR-BID-003 — Bid Immutable

- [ ] No edit route exists for bids
- [ ] No delete route exists for bids (for bidders)
- [ ] Bid cannot be modified after submission

### FR-BID-004 — Auto-Close Bid Submission

- [ ] Auto-close job runs every 60 seconds
- [ ] Job closes all auctions past `end_date`
- [ ] Bid submission disabled immediately on close
- [ ] Close-time invalidation: bidders who did not bid on all CPO-selected assets have bids marked invalid

### FR-BID-005 — Record Timestamp

- [ ] `submitted_at` recorded on every bid
- [ ] Timestamp used for tie-breaking (earliest wins)

## MODULE 11 — Winner Selection

### FR-WIN-001 — Staff Review After Closure

- [ ] Staff can view all bids after auction closes
- [ ] Bids viewable per asset/lot for multi-asset auctions
- [ ] Post-closure review screen available

### FR-WIN-002 — Identify Highest Valid Bid

- [ ] System identifies highest valid bid per asset
- [ ] Reserve price check enforced (bid must meet asset reserve)
- [ ] Tie resolved by earliest `submitted_at` timestamp (BR-008)
- [ ] Invalidated bids excluded from winner selection

### FR-WIN-003 — Record Winner

- [ ] Winner record created per asset for multi-asset auctions
- [ ] Winner record stores auction, asset, bid, user, staff, method
- [ ] `outcome_status` on `auction_assets` updated to `sold` or `unsold`
- [ ] Auction status changes to `closed` at end time regardless of outcomes

### FR-WIN-004 — Winner Notifications

- [ ] Winner notified in-app automatically
- [ ] Winner notified via SMS
- [ ] Winner notified via email
- [ ] If winner declines, next highest valid bidder can be selected (BR-009)
